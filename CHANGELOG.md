# Журнал изменений

Формат версий: `MAJOR.MINOR.PATCH`, предварительные — `.devN` (например, `0.8.0.dev1`).
Версия 1.0.0 — запуск закрытого пилота.

## 0.8.0.dev3 — права доступа, согласия, экспорт и удаление

- Единый слой доступа (`communities/access.py`): закрытые данные видит только подтверждённый житель этого дома. Первый закрытый ресурс — объявления дома (`/api/v1/notices/`); чужой дом и чужое объявление выглядят как «не найдено».
- Доступ закрыт, пока адрес не подтверждён модератором, и пока не приняты актуальные версии согласий.
- Согласия: список, принятие новой версии, отзыв согласия на обработку данных (запускает удаление).
- Экспорт всех данных пользователя (`/api/v1/me/export/`).
- Удаление аккаунта: мгновенное закрытие и всех устройств, окончательное стирание через 30 дней (предварительный срок), вход по коду в этот срок отменяет удаление.
- Роли: группа «Модераторы» (подтверждение адресов и объявления домов, без доступа к личным данным), команда `setup_roles`.
- Админка: объявления домов.

## 0.8.0.dev2 — вход по коду, сессии, регистрация

- Вход по одноразовому коду из e-mail: код хранится только в виде HMAC-хэша, 10 минут жизни, 5 попыток, повторная отправка не чаще раза в минуту, лимиты по e-mail и IP (в базе, без хранения e-mail и IP в открытом виде). Ответ на запрос кода одинаков для любого адреса.
- Вход с любого количества устройств: сессии по устройствам, токен обновления одноразовый (повторное использование отзывает сессию), «выйти здесь», «выйти везде», список устройств, отзыв чужого устройства невозможен.
- Регистрация: подтверждение 18+, согласия с версиями документов, выбор дома, заявка на членство (ожидает подтверждения модератором).
- Профиль: имя, аватар (1–8), необязательный телефон; запрещено менять e-mail, роли и адрес.
- Публичные адреса: справочник ЖК и домов, версии юридических документов.
- Админка: подтверждение или отклонение заявок на адрес.
- Команда `purge_expired` для очистки устаревших записей.
- Исправлен тест миграций (доступ к базе).
- API описан для OpenAPI-схемы (способ входа и формы запросов), схема проверяется тестом.

## 0.8.0.dev1 — каркас нового проекта

Новый проект на Django + PostgreSQL вместо прототипа v0.7.0.2 (подробности: `docs/LEGACY_MAP.md`).

- Каркас репозитория, настройки dev/test/prod через переменные окружения.
- Пользователь (`identity.User`): e-mail как логин, UUID, пароль только у сотрудников.
- Справочник: регион → населённый пункт → ЖК → улица → дом; стартовые данные из v0.7.0.2 (3 ЖК, 23 дома).
- Проверка работоспособности `/api/v1/health/`.
- Автоматические проверки: GitHub Actions, `CHECK_ALL.bat`.
- Вход по коду, согласия, профиль и права доступа — следующие версии M1.
