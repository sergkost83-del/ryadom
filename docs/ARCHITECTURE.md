# Архитектура «РЯДОМ»

## Принципы
1. **Модульный монолит.** Один сервис, внутри — модули с чёткими границами. Микросервисы — только по измеренной необходимости.
2. **Изоляция домов — в одном месте.** Доступ к данным дома определяется единым слоем политик на основе членства, а не проверками в каждом эндпоинте.
3. **Независимость от провайдера.** Docker-образы, обычный PostgreSQL, файлы и бэкапы через S3-совместимый API, почта через SMTP, вся конфигурация — переменные окружения. Перенос = развернуть образы и восстановить бэкап.
4. **Минимум персональных данных.** Не храним сканы документов; телефон необязателен; точный адрес наружу не показывается.
5. **Только работающее.** Нереализованные функции не показываются в интерфейсе (флаги), никаких декоративных кнопок.
6. **Проверка автоматикой.** Каждое изменение проходит тесты в GitHub Actions; изменения схемы — через миграции с проверкой.

## Состав
```
Клиент (Expo: iPhone / Android / веб)  →  HTTPS  →  Django (DRF)  →  PostgreSQL
                                                          ↓
                                              фоновые задачи, почта (SMTP), push
```
Модули: `identity`, `communities`, `chat`, `parking`, `rides`, `support`, `notifications`.
Сделано: `identity` (пользователь, вход, сессии, согласия, профиль), `communities` (справочник, членство).

## Вход и сессии
- Вход по коду из e-mail, пароля у жителей нет. Код: 6 цифр, 10 минут, 5 попыток, хранится как HMAC-хэш с секретом сервера.
- Ограничения: 5 кодов в час на e-mail, 20 на IP, 10 проверок в час на e-mail, 60 на IP. Счётчики в базе, ключи — хэши (e-mail и IP в открытом виде не хранятся).
- Ответ на запрос кода одинаков для любого адреса (нельзя узнать, есть ли аккаунт).
- Сессия на каждое устройство. Access-токен живёт 15 минут, но каждый запрос проверяет сессию в базе, поэтому выход действует сразу. Refresh-токен одноразовый и хранится как SHA-256; повторное использование старого токена отзывает сессию.
- За прокси IP клиента берётся из `X-Forwarded-For` только при заданном числе доверенных прокси (`TRUSTED_PROXY_COUNT`).

## Данные (текущее состояние)
- `Region → Locality → Community (ЖК) → Street → Building (дом)`; идентификаторы UUID; связи PROTECT.
- `User`: e-mail в нижнем регистре (ограничение в БД), UUID, без пароля у жителей, тип аккаунта (сейчас только взрослый), время подтверждения 18+.
- `Membership(пользователь, дом, роль, статус, кто подтвердил, период)`: один активный адрес на пользователя (ограничение в БД), подтверждает модератор в админке.
- `Consent` (версии документов), `Session`, `RefreshToken`, `EmailLoginCode`, `AuthThrottle`.
- Дальше (M1): права доступа по членству, отзыв согласий, экспорт и удаление данных, журнал аудита.

## Окружения
- `dev` — локально, Docker Compose.
- `test` — автотесты (PostgreSQL в CI).
- `prod` — отказывается стартовать без секретного ключа, списка хостов, включает HTTPS-защиты.
