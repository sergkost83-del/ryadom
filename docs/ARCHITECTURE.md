# Архитектура «РЯДОМ»

## Принципы
1. **Модульный монолит.** Один сервис, внутри — модули с чёткими границами. Микросервисы — только по измеренной необходимости.
2. **Изоляция домов — в одном месте.** Доступ к данным дома определяется единым слоем политик на основе членства, а не проверками в каждом эндпоинте.
3. **Независимость от провайдера.** Docker-образы, обычный PostgreSQL, файлы и бэкапы через S3-совместимый API, почта через SMTP, вся конфигурация — переменные окружения. Перенос = развернуть образы и восстановить бэкап.
4. **Минимум персональных данных.** Не храним сканы документов; телефон необязателен; точный адрес наружу не показывается.
5. **Только работающее.** Нереализованные функции не показываются в интерфейсе (флаги), никаких декоративных кнопок.
6. **Проверка автоматикой.** Каждое изменение проходит тесты в GitHub Actions; изменения схемы — через миграции с проверкой.

## Состав
```
Клиент (Expo: iPhone / Android / веб)  →  HTTPS  →  Django (DRF)  →  PostgreSQL
                                                          ↓
                                              фоновые задачи, почта (SMTP), push
```
Модули: `identity`, `communities`, `chat`, `parking`, `rides`, `support`, `notifications`.
Сделано в 0.8.0.dev1: `identity` (пользователь), `communities` (справочник).

## Данные (текущее состояние)
- `Region → Locality → Community (ЖК) → Street → Building (дом)`; идентификаторы UUID; связи PROTECT.
- `User`: e-mail в нижнем регистре (ограничение в БД), UUID, без пароля у жителей.
- Дальше (M1): `Membership(пользователь, дом, роль, статус, кто подтвердил, период)`, согласия с версиями, сессии по устройствам, журнал аудита.

## Окружения
- `dev` — локально, Docker Compose.
- `test` — автотесты (PostgreSQL в CI).
- `prod` — отказывается стартовать без секретного ключа, списка хостов, включает HTTPS-защиты.

## Не сделано (осознанно)
Вход по коду, согласия, права доступа, клиент, чаты, парковка, Попутчик, обращения, push, бэкапы. См. этапы M1–M6.
